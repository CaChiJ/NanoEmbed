# NanoEmbed 코드베이스 가이드

이 가이드는 C++ 코드는 읽을 수 있지만 GGML, GGUF, 트랜스포머는 처음인 개발자를 대상으로 한다. 문서와 소스 코드를 번갈아 보면서 다음 호출이 어떤 과정을 거치는지 이해하는 것이 목표다.

```c
nanoembed_embed(ctx, "hello world", out);
```

호출 하나는 문자열 토큰화, BERT 계산 그래프 구성, 중간 결과용 메모리 할당, CPU 계산, 풀링과 정규화를 거쳐 384개 `float` 값으로 끝난다. 각 장은 이 과정을 이해하는 데 필요한 개념을 앞에서부터 쌓는다.

## 가정하는 배경지식

다음 경험이 있으면 충분하다.

- C 또는 C++ 함수 호출과 객체 수명을 읽을 수 있다.
- 배열의 차원과 행렬곱이 무엇인지 대략 알고 있다.
- CMake 프로젝트를 한 번 이상 빌드해 봤다.

다음 내용은 몰라도 된다.

- GGML의 텐서 축 순서와 메모리 관리
- GGUF 파일 내부 구조
- BERT와 셀프 어텐션의 세부 계산
- WordPiece 토큰화
- RSS, PSS, USS 같은 프로세스 메모리 지표

이 개념들은 코드에서 필요해지는 순서에 맞춰 02장, 03장, 07장에서 설명한다.

## 현재 구현 범위

이 가이드는 현재 작업 트리의 구현을 기준으로 한다.

| 기능 | 상태 |
|---|---|
| BERT 구조의 `bge-small-en-v1.5` | 지원 |
| Gemma 3 구조의 `harrier-oss-v1-270m` | 지원 |
| WordPiece 토크나이저 | 지원 |
| SentencePiece 계열 BPE 토크나이저 | 지원 |
| 단일 문장 임베딩 | 지원 |
| Mean / CLS / Last 풀링 | 지원. 기본값은 모델이 학습된 방식 |
| 여러 문장 API | eager/Linux streaming 실제 B축 batch 지원 |
| 컨텍스트별 그래프 버퍼 재사용 | 지원 |
| `eurobert` 구조와 GPT-2 BPE | 종류만 식별, 실행은 아직 미지원 |
| 레이어별 가중치 스트리밍 | Linux 지원 |
| 실제 레이어 단위 배치 | 지원. Harrier 패킹 후 M5 종료, BERT는 padded/masked 유지 |

현재 구현은 모델 가중치를 모두 메모리에 올린다. 한 번의 추론에서 생기는 중간 결과는 `nanoembed_context`마다 별도 버퍼에 저장하고 다음 호출에서 재사용한다.

이 가이드의 본문은 BERT 경로를 따라간다. 두 번째 계열인 `gemma3`는 위치 인코딩,
정규화, FFN, 어텐션이 모두 다르므로, 각 장에서 대응하는 파일을 함께 짚어 둔다.
구조가 어떻게 다르고 왜 그렇게 갈라졌는지는 `src/arch/gemma3_arch.h`의 머리말과
[마일스톤 해설서](../../milestones-explained.ko.md)의 7장에 있다.

`PLAN.md`에는 완료된 구조와 미래 구조가 함께 나온다. “예정”으로 표시된 클래스나 디렉터리는 아직 소스에 없을 수 있다. 현재 코드 위치를 찾을 때는 [01장의 디렉터리 지도](01-overview.md#현재-디렉터리-구조)를 기준으로 한다.

## 문서에서 사용하는 표현

코드 식별자와 외부 라이브러리 명칭은 원문을 유지한다. 일반 개념은 먼저 한국어로 설명하고, 검색에 필요한 영어 이름을 괄호에 함께 적는다.

- 기준 측정값(`baseline`): 성능 변화를 비교할 때 출발점이 되는 이전 결과
- 테스트 기준 데이터(`fixture`): 올바른 출력이 미리 저장된 파일
- 기준값 테스트: 전체 입력에서 최종 임베딩까지 비교하는 테스트. 실제 파일명은 `golden_test.cpp`다.
- 순전파(`forward`): 입력에서 출력 방향으로 모델 계산을 실행하는 과정
- 미리 확보한 메모리 영역(`arena`): 작은 할당을 반복하지 않도록 큰 연속 공간을 먼저 잡아 두는 방식

용어표는 설명을 대신하지 않는다. 각 장에서는 해당 개념이 처음 나올 때 역할과 수명을 다시 설명한다.
