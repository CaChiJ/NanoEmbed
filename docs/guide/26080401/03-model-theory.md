# 03. BERT 임베딩 모델의 계산 과정

이 장은 텍스트 한 문장이 384개 실수로 바뀌는 과정을 설명한다. 먼저 직관적인 역할을 보고, 그다음 수식과 NanoEmbed의 텐서 차원 크기를 연결한다.

## 입력과 출력

예제로 다음 문장을 사용한다.

```text
the cat sat
```

BERT는 문자열을 직접 계산하지 않는다. 토크나이저가 문자열을 정수 ID 배열로 바꾼다.

```text
문자열
  "the cat sat"

토큰
  [CLS]  the  cat  sat  [SEP]

토큰 ID
  101    ...  ...  ...  102
```

모델은 각 토큰에 384차원 벡터를 만든다. 토큰이 5개라면 인코더의 입력과 출력 차원 크기는 ggml 순서로 `[384, 5, 1]`이다.

마지막에는 토큰 5개의 벡터를 하나로 모아 384차원 문장 벡터를 만든다. 이 작업을 풀링이라고 한다.

```text
문자열 1개
  → 토큰 ID 5개
  → 토큰별 벡터 5 × 384개
  → 문장 벡터 384개
```

## WordPiece 토큰화

BERT의 WordPiece 토크나이저는 두 단계를 거친다.

### 기본 분리

공백과 구두점으로 문자열을 나누고 ASCII 대문자를 소문자로 바꾼다.

```text
"Hello, world!"
  → "hello", ",", "world", "!"
```

현재 NanoEmbed 구현은 ASCII 범위의 공백, 제어 문자, 구두점과 대소문자를 처리한다. 완전한 Unicode 정규화는 아직 구현 범위가 아니다.

### 어휘 조각 찾기

각 단어를 모델 어휘에 있는 가장 긴 조각부터 찾는다. 단어 중간에서 시작하는 조각은 `##` 접두사로 표시한다.

```text
"embedding"
  → "embed" + "##ding"
```

맞는 조각을 찾지 못하면 `[UNK]` ID를 사용한다. 문장 앞에는 `[CLS]`, 뒤에는 `[SEP]`을 붙인다.

최대 길이가 512라면 `[CLS]`와 `[SEP]`도 512 안에 포함된다. 본문 조각이 너무 많으면 뒤를 잘라 마지막 자리를 `[SEP]`에 남긴다.

## 입력 임베딩

정수 토큰 ID는 그대로 행렬곱에 사용할 수 없다. 각 ID를 학습된 벡터로 바꾼다.

BERT는 세 벡터를 더한다.

1. **토큰 임베딩**: 어떤 토큰인지 나타낸다.
2. **위치 임베딩**: 문장의 몇 번째 위치인지 나타낸다.
3. **타입 임베딩**: 문장 쌍 입력에서 어느 문장에 속하는지 나타낸다.

NanoEmbed의 현재 단일 문장 경로에서는 모든 타입 ID가 0이다.

토큰 위치 `i`의 입력 벡터는 다음과 같다.

```text
x_i = token_embedding[token_id_i]
    + position_embedding[i]
    + type_embedding[0]
```

세 벡터를 더한 뒤 LayerNorm을 적용한다.

```text
y = LayerNorm(x)
```

LayerNorm은 한 토큰의 384개 값이 지나치게 크거나 한쪽으로 치우치지 않도록 평균과 분산을 조정한다. 이후 학습된 `gamma`와 `beta`로 크기와 위치를 다시 조절한다.

```text
normalized = (x - mean(x)) / sqrt(variance(x) + epsilon)
y = normalized * gamma + beta
```

NanoEmbed에서는 [`build_embed_layer()`](../../../src/forward/embed_layer.cpp)이 이 계산 그래프를 만든다.

## 셀프 어텐션

입력 임베딩 단계까지는 `cat` 벡터가 어느 문장에 있든 같은 토큰·위치·타입 정보만 가진다. 셀프 어텐션은 각 토큰이 같은 문장의 다른 토큰을 참고해서 문맥에 맞는 표현을 만들게 한다.

예를 들어 `bank`는 다음 두 문장에서 의미가 다르다.

```text
I deposited money at the bank.
We sat on the river bank.
```

어텐션 뒤의 `bank` 벡터는 주변의 `money` 또는 `river` 정보를 서로 다른 비율로 포함할 수 있다.

### Q, K, V를 만드는 이유

각 토큰 벡터 `x`에 서로 다른 학습 행렬을 곱해 Q, K, V 세 벡터를 만든다.

```text
Q = Wq × x + bq
K = Wk × x + bk
V = Wv × x + bv
```

세 이름은 다음 질문으로 이해할 수 있다.

- **Q, Query**: 현재 토큰이 다른 토큰에서 어떤 정보를 찾는가?
- **K, Key**: 이 토큰은 어떤 종류의 정보와 잘 맞는가?
- **V, Value**: 이 토큰을 참고하기로 했을 때 실제로 가져갈 내용은 무엇인가?

Q와 K는 “얼마나 참고할지”를 계산하는 데 사용한다. V는 선택된 정보를 실제로 섞는 데 사용한다. 학습된 행렬을 곱해 새 벡터를 만드는 이 과정을 선형 변환 또는 투영(projection)이라고 부른다.

Q, K, V가 원래 토큰 벡터와 같은 숫자일 필요는 없다. 세 학습 행렬이 서로 다른 관점으로 토큰을 투영한다.

### Q와 K의 내적으로 관련도를 구한다

현재 토큰의 Q와 모든 토큰의 K를 내적한다. 내적값이 크면 두 벡터가 비슷한 방향이라는 뜻이다.

토큰이 세 개라고 가정해 보자.

```text
토큰: [the, cat, sat]
```

`sat`의 Q와 각 토큰의 K를 내적한 결과가 다음과 같다고 가정한다. 이 숫자는 설명용이며 실제 모델 값이 아니다.

```text
Q_sat · K_the = 0.2
Q_sat · K_cat = 1.8
Q_sat · K_sat = 0.7
```

이 단계에서는 `sat`가 `cat`과 가장 관련 있다고 판단했다. 하지만 1.8 자체는 비율이 아니며 세 값의 합도 1이 아니다.

### `√head_dim`으로 나눈다

벡터 차원이 커지면 내적은 여러 곱셈의 합이므로 절댓값도 커지는 경향이 있다. 큰 점수를 그대로 softmax에 넣으면 가장 큰 항목 하나가 거의 1이 되고 나머지는 0에 가까워질 수 있다.

이를 완화하기 위해 점수를 헤드 차원의 제곱근으로 나눈다.

```text
scaled_score(q, k) = (Q_q · K_k) / sqrt(head_dim)
```

bge-small은 hidden 차원 384를 12개 헤드로 나누므로 `head_dim`은 32다.

```text
head_dim = 384 / 12 = 32
scale = 1 / sqrt(32)
```

### softmax로 가중치를 만든다

softmax는 점수 목록을 0과 1 사이 값으로 바꾸고 합을 1로 만든다.

앞의 설명용 점수가 softmax 뒤에 다음처럼 바뀌었다고 가정한다.

```text
the: 0.12
cat: 0.68
sat: 0.20
합계: 1.00
```

이제 각 숫자는 `sat`의 새 표현을 만들 때 해당 토큰 정보를 어느 비율로 가져올지 나타낸다.

수식으로는 다음과 같다. `q`는 정보를 받는 토큰 위치, `k`는 참고할 토큰 위치다.

```text
attention_weight[q, k]
  = softmax_k((Q[q] · K[k]) / sqrt(head_dim))
```

`softmax_k`는 한 query 위치에서 모든 key 위치에 대해 softmax를 적용한다는 뜻이다.

### 가중치로 V를 합친다

앞에서 만든 가중치로 각 토큰의 V를 곱해 더한다.

```text
output_sat
  = 0.12 × V_the
  + 0.68 × V_cat
  + 0.20 × V_sat
```

이 결과에는 `sat` 자신의 정보뿐 아니라 `cat`과 `the`의 정보도 들어 있다. 그래서 셀프 어텐션 뒤의 토큰 벡터는 문맥에 따라 달라진다.

전체 수식은 다음과 같다.

```text
Attention(Q, K, V)
  = softmax(QKᵀ / sqrt(head_dim)) V
```

NanoEmbed의 ggml 호출은 축 배치 때문에 코드에서 `KᵀQ` 형태로 보인다. 의미는 각 query와 key의 내적 점수를 만들고 그 가중치로 V를 합치는 같은 계산이다.

### 멀티헤드로 여러 관점을 계산한다

하나의 큰 어텐션만 계산하지 않고 384차원을 12개 묶음으로 나눈다. 각 헤드는 32차원 Q, K, V로 독립적인 관련도를 계산한다.

헤드마다 별도 가중치 행렬 구간을 사용하므로 서로 다른 관계에 반응할 수 있다. 어떤 헤드는 가까운 수식어에, 다른 헤드는 문장의 주어와 동사 관계에 더 민감할 수 있다. 이것은 가능한 해석이며 특정 헤드가 반드시 특정 문법만 담당한다는 뜻은 아니다.

계산이 끝나면 12개 헤드의 32차원 출력을 다시 이어 384차원으로 만든다. 출력 선형 변환을 한 번 더 적용해 헤드 정보를 섞는다.

```text
[32, S, 12, B]
  → 헤드 결합
[384, S, B]
  → 출력 선형 변환
[384, S, B]
```

### NanoEmbed의 어텐션 차원 변화

`H=384`, `n_head=12`, `head_dim=32`, 토큰 수를 `S`라고 하면 [`build_attention_block()`](../../../src/forward/attention.cpp)은 다음 차원 크기를 사용한다.

| 단계 | ggml 차원 크기 | 의미 |
|---|---|---|
| 입력 `x` | `[H, S, B]` | 토큰별 hidden 벡터 |
| Q, K, V 선형 변환 | `[H, S, B]` | 세 관점의 토큰 표현 |
| 헤드 분리 | `[head_dim, n_head, S, B]` | 384를 12×32로 분리 |
| 축 변경 | `[head_dim, S, n_head, B]` | 헤드별 행렬곱 배치 |
| 점수 | `[S_key, S_query, n_head, B]` | query-key 관련도 |
| softmax | 같은 차원 크기 | key축 합이 1인 가중치 |
| V 가중합 | `[head_dim, S_query, n_head, B]` | 문맥이 섞인 헤드 출력 |
| 헤드 결합 | `[H, S, B]` | 토큰별 384차원 출력 |

현재 단일 문장 경로는 패딩이 없으므로 어텐션 마스크가 `nullptr`이다. M5에서 길이가 다른 문장을 한 배치로 묶으면 패딩 위치를 무시하는 마스크가 필요하다.

## 잔차 연결과 LayerNorm

어텐션 결과만 다음 단계로 보내지 않고 입력을 다시 더한다.

```text
y = LayerNorm(x + Attention(x))
```

`x + Attention(x)`의 `x`가 잔차 연결이다. 어텐션이 만든 변화와 원래 토큰 표현을 함께 보존한다.

bge-small의 BERT는 합한 뒤 LayerNorm을 적용하는 post-LN 구조다. 다른 모델 구조는 정규화 위치가 다를 수 있으므로 `ModelArch`별 구현이 필요하다.

## 피드포워드 네트워크

어텐션은 토큰 사이 정보를 섞는다. 그다음 FFN은 각 토큰 벡터를 같은 방식으로 개별 변환한다.

```text
[H=384]
  → 차원을 늘리는 선형 변환
[F=1536]
  → GELU
[F=1536]
  → 차원을 줄이는 선형 변환
[H=384]
```

수식은 다음과 같다.

```text
h = GELU(W_up × x + b_up)
z = W_down × h + b_down
out = LayerNorm(x + z)
```

차원을 384에서 1,536으로 넓히면 각 토큰을 더 큰 내부 공간에서 비선형적으로 변환할 수 있다. 다시 384로 줄여 다음 레이어와 차원 크기를 맞춘다.

NanoEmbed는 Hugging Face BERT 설정과 맞추기 위해 erf 기반의 정확한 GELU인 `ggml_gelu_erf`를 사용한다. tanh 근사 버전을 사용하면 한 레이어의 작은 차이가 12개 레이어를 지나며 누적될 수 있다.

[`build_ffn_block()`](../../../src/forward/ffn.cpp)이 이 계산을 만든다.

## BERT 인코더 블록과 전체 스택

한 BERT 인코더 블록은 두 부분이다.

```text
입력
  → 멀티헤드 셀프 어텐션
  → 잔차 연결 + LayerNorm
  → FFN
  → 잔차 연결 + LayerNorm
  → 출력
```

[`build_encoder_block()`](../../../src/forward/encoder_block.cpp)은 어텐션 빌더와 FFN 빌더를 순서대로 연결한다.

`BertModelArch::build_graph()`는 이 블록을 12번 연결한다. 각 블록은 `[384, S, B]`를 받아 같은 차원 크기를 반환하지만, 레이어마다 다른 학습 가중치를 사용한다.

```text
입력 임베딩
  → block 0
  → block 1
  → ...
  → block 11
  → 토큰별 최종 hidden state
```

현재는 12개 레이어 가중치를 모두 메모리에 둔 채 전체 그래프를 만든다. M4의 스트리밍은 같은 논리적 순서를 유지하면서 한 번에 한 레이어의 가중치만 상주시키는 것이 목표다.

## 풀링

인코더 출력에는 토큰마다 하나의 384차원 벡터가 있다. 문장 임베딩 API는 문장 하나당 벡터 하나를 반환해야 하므로 토큰 축을 줄인다.

### Mean 풀링

모든 토큰 벡터의 평균을 낸다.

```text
sentence = (x_0 + x_1 + ... + x_(S-1)) / S
```

현재 단일 문장 경로에는 패딩이 없으므로 단순 평균을 사용한다. 실제 배치에서는 패딩 토큰을 평균에서 제외해야 한다.

### CLS 풀링

첫 토큰 `[CLS]`의 최종 벡터만 사용한다.

```text
sentence = x_0
```

`bge-small-en-v1.5`의 sentence-transformers 설정과 비교할 때는 CLS 풀링을 사용한다. 공개 API의 기본값은 Mean이므로 기준값 테스트는 CLS를 명시한다.

### Last 풀링

마지막 토큰의 벡터를 사용한다. 현재 내부 그래프 빌더에는 구현되어 있지만, 이를 기본으로 사용하는 eurobert 모델은 아직 지원하지 않는다. 실제 배치가 들어오면 각 문장의 마지막 유효 토큰을 마스크로 찾아야 한다.

## L2 정규화

풀링한 벡터를 길이 1로 맞춘다.

```text
normalized = x / ||x||₂
```

여기서 `||x||₂`는 모든 원소 제곱의 합에 제곱근을 취한 값이다.

L2 정규화된 두 벡터의 내적은 코사인 유사도와 같다. 검색에서 매번 두 벡터의 길이로 나누지 않고 내적만 계산할 수 있다.

## 전체 계산 흐름

```text
문자열
  ↓ WordPiece
토큰 ID + 위치 ID + 타입 ID
  ↓ 임베딩 조회와 합
입력 벡터 [H, S, B]
  ↓ LayerNorm
  ↓ BERT 블록 × 12
     ├─ Q, K, V 선형 변환
     ├─ scaled dot-product attention
     ├─ 출력 선형 변환
     ├─ 잔차 연결 + LayerNorm
     ├─ FFN up + GELU + down
     └─ 잔차 연결 + LayerNorm
토큰별 최종 벡터 [H, S, B]
  ↓ Mean / CLS / Last 풀링
문장 벡터 [H, B]
  ↓ 선택적 L2 정규화
최종 임베딩
```

## 이 장의 핵심 정리

- WordPiece는 문자열을 어휘 조각 ID로 바꾸고 `[CLS]`, `[SEP]`을 붙인다.
- BERT 입력은 토큰, 위치, 타입 임베딩을 더한 뒤 정규화한 값이다.
- Q와 K의 내적은 토큰 간 참고 비율을 계산하고, 그 비율로 V를 합쳐 문맥을 반영한다.
- `sqrt(head_dim)` 스케일은 큰 내적이 softmax를 지나치게 한쪽으로 몰지 않게 한다.
- 멀티헤드는 hidden 차원을 여러 작은 관점으로 나눠 어텐션을 계산한다.
- FFN은 각 토큰을 독립적으로 384→1,536→384 차원으로 변환한다.
- 12개 블록 뒤의 토큰 벡터를 풀링하고 L2 정규화해 문장 임베딩을 만든다.
